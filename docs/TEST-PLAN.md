## Verifier properties

Status never becomes current solely from a client field, planner output, ACK or human override. Every current result has one accepted evidence chain and valid bindings. State versions and sequences are monotone. Events are exactly-once at the application operation level. No stale commit wins a race. Delete denies reads before asynchronous cleanup. Promotion cannot see frozen labels while fitting. Unknown/extra objects cannot disappear from the accounting by confidence filtering. Test generated event sequences against these independent invariants.

## Evaluation protocol

Plan 144 held-out episodes: three recipes x six conditions x eight independent setups. Conditions: complete, missing, wrong visible variant, overlap, glare and post-pass removal. Count ground-truth-complete and ground-truth-incomplete episodes separately; glare does not automatically mean incomplete. Supplement with state/fault/adversarial cases; do not pretend these are independent physical episodes. Development data are additional and cannot be reused as untouched test data.

With no current kits/operators, initial 144 episodes may be synthetic and must be labeled as such. Physical validation replaces neither metadata nor labels silently: create a new physical dataset version. Test grouping is by physical setup/session/operator to prevent neighboring-frame leakage. If availability forces a smaller study, record actual N and limit claims; do not fabricate the target sample size.

Baselines: single-image measurement, equal-budget fixed recapture checklist, strong deterministic rule policy, and candidate adaptive policy; compare an LLM proposal mode only if implemented and used. Fix maximum actions/time and capture opportunities; use randomized/counterbalanced order or equivalent paired setups to avoid learning/fatigue confounds. A replay benchmark alone cannot measure human time savings; real interaction timing is required.

Metrics: correct completions / total operator-hours; incorrect passes / ground-truth-incomplete inspections; incorrect rejections / ground-truth-complete inspections; unresolved / all inspections; time to result; action count; task recovery; per-constraint precision/recall; p50/p95 service latency; cost per completed inspection. Report denominators, confidence intervals and paired differences. Use cluster/bootstrap intervals by independent session when feasible; tiny session counts require descriptive reporting. For zero incorrect passes among n independent incomplete cases, the one-sided 95% binomial upper bound is `1 - 0.05^(1/n)`; zero observations are not zero risk, and correlated cases weaken that calculation.

Learning experiment: build V0 on development partition, add reviewed intervention data only to development, build V1, compare both on untouched test partition against rules. Improvement must come from data accumulation, not different compute budgets or access to answers. Preserve failed runs and report no advantage if V1 does not outperform. Three-session minimum is a planning target, not sufficient production validation.
